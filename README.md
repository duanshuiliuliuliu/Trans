# Trans

划词翻译托盘工具：用鼠标划选文字，译文以卡片形式出现在光标旁。默认调用 DeepSeek 接口，运行时不依赖任何第三方库，适用于 Windows 10 / 11。

> 最初的需求：仅有一个托盘；双击托盘弹出设置（配置大模型 key 与自定义规则）；右键托盘可启用/禁用；内存占用尽可能小，设计简单明了。

## 特性

| 能力 | 说明 |
| --- | --- |
| 划选取词 | 鼠标划选文字即触发翻译，支持「任意划选」与「仅按住 Ctrl 划选」两种模式 |
| 翻译规则 | 按原文语言选择目标语言，覆盖 43 种主流亚欧语种；本地判不出的语种交给模型判断 |
| 结果卡片 | 圆角卡片、置顶但不抢焦点、可拖动/复制/选中文本，支持浅色与暗色 |
| 托盘 | 单实例；只有启用/禁用、设置、退出三项 |
| 多显示器 | 弹窗出现在选中文字所在的那块屏幕 |
| 资源占用 | 常驻约 40 MB；不加载本地模型、不使用 GPU |

## 快速开始

### 源码运行

双击 `Trans.pyw`（`.pyw` 不弹控制台），或：

```powershell
pythonw Trans.pyw
```

需要 Python 3.10 以上（开发验证环境 3.14.3）且带 `tkinter`。**不需要 `pip install` 任何包**。

### 打包成 exe（可选）

```bat
python -m pip install pyinstaller
build.bat            rem 默认单文件：dist\Trans.exe
build.bat onedir     rem 目录形式：dist\Trans\Trans.exe（启动更快，但整个目录都要拷走）
```

`build.bat` 可直接双击。单文件产物约 12 MB，拷到任何 Windows 10/11 机器双击即用，**目标机器无需安装 Python**（运行时、Tcl/Tk、图标资源都在里面），首次启动约 1.8 秒（自解压到 `%TEMP%`）。

程序是**单实例**的：重复启动不会产生第二个进程，第二次点击会把已在运行的实例的设置窗口调到前台。源码方式与 exe 共用同一把互斥体，两者同时只能跑一个。

## 使用

1. 托盘图标右键 →「设置」，先在「大模型」页填 API Key（见下方「首次配置」）。
2. 用鼠标选中文字：默认要**按住 Ctrl** 再拖选，避免日常选字被误翻译；也可以在设置里改成「鼠标划选后自动翻译」。
3. 松开鼠标后稍等片刻，译文卡片出现在光标右下侧，8 秒后自动消失（可配置）。卡片上可按住顶部一行拖动、选中译文、点「复制」；点击卡片以外的位置立即关闭。

托盘右键菜单只有三项：启用/禁用（图标随状态变灰）、设置、退出。双击托盘图标也是打开设置。

取词失败时（例如拖拽窗口、拖拽文件），程序静默放弃并还原剪贴板，不会误翻译。

### 首次配置

「大模型」页：

| 项 | 说明 |
| --- | --- |
| 接口地址 | 默认 `https://api.deepseek.com`；也接受 `…/v1` 或任何 OpenAI 兼容地址 |
| API Key | DeepSeek 控制台创建；保存时用 Windows DPAPI 加密，不落明文 |
| 模型 | 默认 `deepseek-flash`（快），也可用 `deepseek-v4-pro` |
| 翻译前先推理 | 默认**不勾**：响应快一倍；勾上质量略好，适合术语密集的难句 |
| 温度 | 默认 0.3；关闭推理时低温度能减少「原文词语没译出来」之类的随机问题 |
| 超时（秒） | 默认 20 |
| 翻译提示词 | `{target}` 会替换为目标语言名称 |

填好后点「保存并应用」，选一段文字试一下。Key 有误会直接把接口报错显示在卡片里。

## 设置项

### 通用

| 项 | 说明 |
| --- | --- |
| 启用取词翻译 | 总开关，等同托盘菜单的「禁用」；关闭时下面两种取词方式不可选 |
| 鼠标划选后自动翻译 | 任意划选都翻译 |
| 仅按住 Ctrl 划选时翻译 | 默认；只有按住 Ctrl 拖选才翻译，日常选字不受影响 |
| 弹窗中显示原文 | 卡片顶部附带原文摘要 |
| 暗色模式（翻译弹窗） | 卡片切换为深色配色 |
| 弹窗自动关闭 | 秒数，0 表示不自动关闭 |
| 字号 | 卡片正文字号 |

页面底部还有「打开配置目录」「打开日志」两个按钮。

### 翻译规则

列表自上而下匹配，第一条命中的生效；可增删、编辑、调整顺序。默认两条：

| 识别到的原文语言 | 翻译为 |
| --- | --- |
| 中文（含日文汉字） | 英语 |
| 自动识别（兜底） | 中文 |

页面底部可设置最长翻译字符数（默认 3000，超出会截断并在卡片上标注「已截断」）。

### 语言支持与识别

规则里的源语言与目标语言覆盖 43 种主流亚欧语种（下拉里另有「自动识别」共 44 项）：中文、繁体中文、日语、韩语、越南语、泰语、印尼语、马来语、印地语、孟加拉语、泰米尔语、阿拉伯语、波斯语、希伯来语、土耳其语、英语、德语、法语、西班牙语、葡萄牙语、意大利语、荷兰语、加泰罗尼亚语、瑞典语、挪威语、丹麦语、芬兰语、冰岛语、波兰语、捷克语、斯洛伐克语、匈牙利语、罗马尼亚语、保加利亚语、希腊语、俄语、乌克兰语、塞尔维亚语、克罗地亚语、斯洛文尼亚语、立陶宛语、拉脱维亚语、爱沙尼亚语。目标语言还支持自定义输入（如「文言文」）。

本地识别按字符脚本与特征字母进行，不额外消耗接口调用：

| 情况 | 行为 |
| --- | --- |
| 中日韩、希腊、希伯来、阿拉伯、印地语、泰语、俄语、乌克兰语等按脚本可分的语种 | 本地识别，精确命中对应规则 |
| 越南语、土耳其语、波兰语、捷克语、匈牙利语、葡萄牙语、冰岛语等有独有特征字母的语种 | 命中特征字母时本地识别 |
| 纯拉丁字母且本地判不出（英/法/德/西/意/荷…） | 把整张规则表交给模型判断目标语言 |

所以像「法语 → 德语、其它 → 中文」这样的规则也能生效：法语文本在本地判不出时，由模型按规则表选择德语。这条路径不增加调用次数，实测延迟仍在 1 秒出头。

## 配置文件

- 路径：`%APPDATA%\Trans\config.json`（「通用」页有「打开配置目录」）
- API Key 经 DPAPI 加密，仅当前 Windows 用户可解密；手动写明文也能识别
- 保存后立即生效，无需重启
- 日志：`%APPDATA%\Trans\trans.log`（超过 512 KB 自动轮转）；崩溃调用栈单独写在同目录的 `crash.log`

设置界面没有暴露的参数，需要时直接改配置文件（改完重启）：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `trigger.min_drag_px` | 4 | 拖动小于该像素数不算划选 |
| `trigger.copy_delay_ms` | 130 | 松开鼠标后等多久再模拟复制；个别程序取不到词时调大 |
| `trigger.restore_clipboard` | `auto` | 剪贴板还原：`auto` / `always` / `never` |
| `debug` | `false` | 是否记录详细调试日志（崩溃栈与卡顿告警始终会写） |

### 剪贴板行为

取词依赖模拟 `Ctrl+C`，因此会经过系统剪贴板。默认「智能」策略：翻译前剪贴板若只有纯文本，结束后自动还原；若含图片、文件、HTML 等富格式则不做还原，以免把富内容覆盖成纯文本。

## 性能

单次翻译实测（同一台笔记本、真实接口）：

| 配置 | 平均耗时 | 输出 token（其中推理） |
| --- | --- | --- |
| 翻译前先推理（勾选） | 2.18s | 143~266（130~246） |
| 翻译前先推理（默认不勾） | **1.01s** | 13~21（0） |
| 接口地板延迟（最短请求） | 1.01s | — |

时间几乎都花在模型的隐藏推理上（一次调用 234 个输出 token 里 212 个是推理），所以默认关闭。关闭后已贴近接口自身的固定开销，网络与参数层面没有可压缩空间；连接复用、流式输出、精简提示词三条路线都实测过，收益在噪声级或小于 0.2 秒，因此没有采用。

## 打包与分发

| 事项 | 说明 |
| --- | --- |
| 配置与 Key | 不在 exe 内；新机器首次运行自动建 `%APPDATA%\Trans\config.json`，填一次 Key 即可 |
| 代码签名 | 未签名，从网络拷过去首次运行可能被 SmartScreen 拦一下（「更多信息 → 仍要运行」） |
| 单文件 vs 目录 | 单文件启动慢约 1 秒（每次自解压）；`onedir` 启动更快，但必须整个目录一起拷 |
| 重新打包 | 先退出正在运行的 exe（运行中的 exe 会锁住 `dist`，脚本会拦住你） |
| 脚本编码 | `build.bat` 只用 ASCII：`cmd.exe` 按控制台代码页读取 bat，中文会乱码甚至导致解析失败 |

## 已知限制

- 只支持鼠标划选取词；用键盘（Shift+方向键、Ctrl+A）选中的文字不会触发翻译。
- 以管理员权限运行的窗口（UAC 提权程序）取不到词，需要覆盖时请以管理员身份运行 Trans。
- 少数程序（部分终端模式、游戏内嵌浏览器、远程桌面画面）不响应模拟 `Ctrl+C`，这类窗口里取不到词，日志会记一条「未取到选中文本」。
- 语言识别是启发式规则，混排文本可能判为占比更大的语种；纯拉丁语种交给模型判断。
- 不同缩放比例的显示器上，弹窗字号仍按主屏缩放计算（Tk 8.6 的限制），在高 DPI 副屏上可能略小。
- 触摸板驱动、鼠标增强软件、远程桌面会把鼠标事件标记为「注入（injected）」；程序不过滤这类事件，这些环境下可正常取词。

## 隐私

划选到的文本会通过 HTTPS 发送到你配置的接口用于翻译；除此之外不发起任何网络请求，也不上传本地数据。译文、日志与配置都只留在本机。

## 开发

```powershell
python -m compileall app Trans.pyw tools   # 语法检查
python tools/selftest.py                   # 93 项非交互自检
python tools/integration_test.py           # 端到端自检（需已配置 API Key）
python tools/bench_latency.py              # 延迟基准
```

自检覆盖结构体布局、语言检测、规则匹配、接口拼装、配置读写与密钥加密、剪贴板、原生窗口与消息泵、托盘注册、鼠标钩子、划选识别（含 Ctrl 门控）、弹窗渲染与关闭、托盘菜单项、单实例与上次异常退出检测。托盘菜单交互、真实划选取词需人工验证。

排障：把配置里的 `debug` 改成 `true` 并重启，复现一次后查看 `%APPDATA%\Trans\trans.log`。

- 有「检测到划选」→ 钩子正常，问题在后续取词或翻译环节
- 完全没有记录 → 用 `python tools/hook_probe.py 20` 确认鼠标事件是否到达程序
- 有 `WARN 主线程卡住 …（最近动作：…）` → 主线程被阻塞，其后附有当时的调用栈
- 程序意外消失 → 下次启动会写一条 `WARN 上次运行没有正常退出`，崩溃栈在 `crash.log`

### 设计约束（改代码时请遵守）

- **鼠标钩子回调里只允许记录状态**（几何判断、入队）。钩子由系统在消息泵内部同步调用，回调里做 Tk 操作会重入消息泵，最坏情况递归到栈溢出把进程打死，表现为「鼠标变卡、几秒后程序消失」。
- **剪贴板只能在 worker 线程里碰**。`OpenClipboard` 是跨进程独占锁，可能被别的程序占住几百毫秒到几秒；在主线程等待期间钩子无法被及时服务，整机鼠标都会卡。
- **弹窗关闭是「先隐藏、160ms 后再销毁」**，避免鼠标按键仍按下时销毁窗口（隐式鼠标捕获会指向已销毁的窗口）。
- **托盘菜单在 Tk 定时器上下文弹出**，不在窗口过程（消息分发）里开模态循环。
