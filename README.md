# Trans

## description

此工程是一个极简工具，其主要功能是： 翻译鼠标选中的文字为指定语言文字，支持配置翻译规则（如 默认翻译为中文，选中中文时默认翻译为英语）

1. 仅有一个托盘
2. 双击托盘弹出设置界面，设置界面里可以配置大模型key和自定义规则
3. 右键托盘，弹出禁用/启用 选项

要求软件内存占用要尽可能小，设计要简单明了

## 实现说明

- 语言：Python 3，界面用标准库 tkinter，其余全部通过 ctypes 直调 Win32（托盘、热键、鼠标钩子、剪贴板、DPAPI），**运行时零第三方依赖**。
- 大模型：DeepSeek 官方接口（OpenAI 兼容的 `/chat/completions`），默认模型 `deepseek-chat`。
- 单进程 + 一个隐藏窗口；设置窗口与结果弹窗按需创建、用完销毁，空闲内存约 30~40 MB。

## 运行

直接双击 `Trans.pyw`（`.pyw` 不弹控制台窗口），或在仓库根目录执行：

```powershell
pythonw Trans.pyw
```

需要 Python 3.10 或更高版本（开发验证环境为 3.14.3），且 `tkinter` 可用。无需 `pip install` 任何包。

程序是**单实例**的：无论源码方式还是打包后的 exe，重复双击都不会起第二个进程——第二次点击会把已在运行的实例的设置窗口调到前台。源码方式与 exe 共用同一把互斥体，因此两种方式同时只能跑一个。

打包成免安装 exe（可选，需要先 `pip install pyinstaller`）：

```bat
python -m pip install pyinstaller
build.bat            rem 默认单文件，产物 dist\Trans.exe
build.bat onedir     rem 目录形式，产物 dist\Trans\Trans.exe（启动更快，但整个目录都要拷走）
```

`build.bat` 可以直接双击运行（双击等于默认的单文件模式），首次打包约 10 秒。产物是**单文件** `dist\Trans.exe`（约 12 MB）：拷到任何 Windows 10/11 机器上双击就能跑，**不需要目标机器安装 Python**——Python 运行时、Tcl/Tk 和图标资源都打包在里面，启动时自解压到 `%TEMP%`，实测首启动约 1.8 秒。

几点需要知道：

| 事项 | 说明 |
| --- | --- |
| 配置与 API Key | 不在 exe 里，存在 `%APPDATA%\Trans\config.json`（Key 用 DPAPI 加密，只能当前 Windows 用户解密）。新机器首次运行会自动建目录，在设置里填一次 Key |
| 代码签名 | 未签名，从网络拷过去首次运行可能被 SmartScreen 拦一下（“更多信息 → 仍要运行”） |
| 打包模式差异 | 单文件启动慢约 1 秒（每次自解压）；`onedir` 启动更快但必须整个目录一起拷，单独拷 exe 无法运行 |
| 脚本编码 | `build.bat` 刻意只用 ASCII：`cmd.exe` 按控制台代码页（中文 Windows 是 GBK）读取 bat，非 ASCII 文字会变乱码甚至导致解析失败 |
| 重新打包 | 打包前要先从托盘菜单退出正在运行的 exe，否则脚本会拦住你并提示（运行中的 exe 会锁住 dist） |

## 首次配置

托盘图标右键 →「设置」（或双击托盘图标），在「大模型」页填写：

| 项 | 说明 |
| --- | --- |
| 接口地址 | 默认 `https://api.deepseek.com`，也支持 `https://api.deepseek.com/v1` 或任何 OpenAI 兼容地址 |
| API Key | DeepSeek 控制台创建的 key，保存时用 Windows DPAPI 加密，不落明文 |
| 模型 | 默认 `deepseek-flash`（快，适合划词场景），也可用 `deepseek-v4-pro` |
| 温度 | 默认 0.3。关闭推理后调低温度能明显降低随机性（避免漏译术语） |
| 翻译前先推理 | 默认**不勾**。不勾时响应快得多（实测 1.0s vs 2.2s），勾上质量略好 |
| 翻译提示词 | `{target}` 会被替换为目标语言名称 |

填好后点「保存并应用」。选一段文字试一下，若 Key 有误会直接在弹窗里显示接口报错。

## 延迟优化

实测发现这条链路的时间几乎全花在模型的隐藏推理上：一次普通翻译返回 234 个输出 token，其中 **212 个是推理 token**，真正的译文只占 20~30 个。所以默认关闭推理：

| 配置 | 平均耗时 | 输出 token（其中推理） |
| --- | --- | --- |
| 推理开启 | 2.18s | 143~266（130~246） |
| 推理关闭（默认） | **1.01s** | 13~21（0） |
| 接口地板延迟（最短请求） | 1.01s | — |

关闭推理后已经贴到接口本身的固定开销，网络和参数层面没有可压缩空间了。同时验证过并放弃的做法：连接复用（两次测量结果互相矛盾，收益淹没在噪声里）、流式输出（译文只有 20~30 个 token，首字只比整体早约 0.2s）、精简提示词（收益 <0.1s）。

需要更高质量时，在「大模型」页勾上「翻译前先推理」。难句、术语密集的句子建议开启。

## 使用方式

- **划选即译**：两种方式在设置里二选一——「仅按住 Ctrl 划选时翻译」（默认，日常选字不会被误翻译）或「鼠标划选后自动翻译」（任意划选都翻译）。松开鼠标后稍等片刻，译文弹窗会出现在光标旁。
- **快捷键**：`Ctrl+Alt+T`，先用任意方式选中文字（含键盘选中），再按这个键取词翻译。
- **快捷键**：默认 `Ctrl+Alt+T`，翻译当前选中文本（适合鼠标钩子不生效的窗口）。
- **托盘右键菜单**：只有启用/禁用、设置、退出三项。禁用后托盘图标转为灰色；双击托盘图标直接打开设置。
- **结果弹窗**：白底圆角卡片（Windows 11 原生圆角，Windows 10 为直角），左侧竖条用颜色区分状态——蓝色是译文、淡蓝是翻译中、红色是出错；可拖动（按住顶部一行）、可选中译文、点「复制」写入剪贴板；鼠标移入时暂停自动关闭，移开后按设定秒数关闭；点击弹窗以外的位置立即关闭。

## 翻译规则

「翻译规则」列表里的源语言和目标语言覆盖 44 种主流亚欧语种：中文（含繁体）、日语、韩语、越南语、泰语、印尼语、马来语、印地语、孟加拉语、泰米尔语、阿拉伯语、波斯语、希伯来语、土耳其语、英语、德语、法语、西班牙语、葡萄牙语、意大利语、荷兰语、加泰罗尼亚语、瑞典语、挪威语、丹麦语、芬兰语、冰岛语、波兰语、捷克语、斯洛伐克语、匈牙利语、罗马尼亚语、保加利亚语、希腊语、俄语、乌克兰语、塞尔维亚语、克罗地亚语、斯洛文尼亚语、立陶宛语、拉脱维亚语、爱沙尼亚语。默认规则：

| 识别到的原文语言 | 翻译为 |
| --- | --- |
| 中文（含日文汉字） | 英语 |
| 自动识别（兜底） | 中文 |

规则自上而下匹配，第一条命中的生效，可增删、可调整顺序；目标语言也支持自定义输入（如「文言文」）。「翻译规则」页还可配置最长翻译字符数（超出会被截断并在弹窗里标注）。

### 语言识别能力

程序先在本地按字符脚本和特征字母判断原文语言，不额外消耗接口调用，但纯拉丁字母的语种（英语、法语、德语、西班牙语…）在本地无法可靠区分。所以：

| 情况 | 行为 |
| --- | --- |
| 中日韩、希腊、希伯来、阿拉伯、印地语、泰语、俄语、乌克兰语等按脚本可分的语种 | 本地识别，精确命中对应规则 |
| 越南语、土耳其语、波兰语、捷克语、匈牙利语、葡萄牙语、冰岛语等有独有特征字母的语种 | 命中特征字母时本地识别，否则按下一行处理 |
| 纯拉丁字母且本地判不出（英/法/德/西/意/荷…） | **把整张规则表交给模型判断**，由模型决定目标语言 |

举例：配置「法语→德语、其它→中文」后，选中法语文本会输出德语译文；配置「中文→英语、其它→中文」时，英法德西等文本都会译为中文。交给模型路由时不增加调用次数，实测延迟仍在 1 秒出头。

## 剪贴板行为

取词依赖模拟 `Ctrl+C`，因此会经过系统剪贴板。策略固定为默认的「智能」：翻译前剪贴板若只有纯文本，翻译结束后自动还原；若包含图片、文件、HTML 等富格式，则不做还原以免破坏原内容。需要改成「总是还原」或「不还原」，直接改配置文件里的 `trigger.restore_clipboard`。

## 界面里没有暴露的选项

为了让设置界面保持简单，「通用」页只保留启用开关、取词方式、弹窗显示原文、弹窗自动关闭、字号五项。以下参数固定使用默认值，需要调整时改 `%APPDATA%\Trans\config.json`（改完重启程序）：

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| `trigger.hotkey` | `Ctrl+Alt+T` | 取词快捷键，格式如 `Ctrl+Shift+F2` |
| `trigger.min_drag_px` | 4 | 拖动小于该像素数不算划选 |
| `trigger.copy_delay_ms` | 130 | 松开鼠标后等多久再取词，个别程序取不到时可调大 |
| `trigger.restore_clipboard` | `auto` | 剪贴板还原策略：`auto` / `always` / `never` |
| `debug` | `false` | 是否记录详细调试日志（崩溃栈与卡顿告警不受它影响，始终会写） |

## 配置文件

- 位置：`%APPDATA%\Trans\config.json`（「通用」页有「打开配置目录」按钮）
- API Key 以 DPAPI 加密存储，仅当前 Windows 用户可解密；手工填写明文 key 也能识别
- 日志：`%APPDATA%\Trans\trans.log`，超过 512 KB 自动轮转；崩溃栈单独写在同目录的 `crash.log`
- 保存后立即生效，无需重启

## 开机自启

程序不自动写入自启项。如需开机启动，在「运行」中输入 `shell:startup` 打开启动文件夹，把 `Trans.pyw`（或打包后的 `Trans.exe`）的快捷方式放进去即可。

## 已知限制

- 取词识别依赖低级鼠标钩子：以管理员权限运行的窗口（UAC 提权程序）无法被普通权限进程取词，如需覆盖请以管理员身份运行 Trans。
- 触摸板驱动、鼠标增强软件、远程桌面等会把自己的鼠标事件标记为「注入（injected）」。程序不过滤这类事件，因此这些环境下同样可以正常取词。
- 用键盘（Shift+方向键、Ctrl+A）选中文字不会触发翻译，请按 `Ctrl+Alt+T`。
- 少数程序（部分终端模式、游戏内嵌浏览器、远程桌面画面）不响应模拟 `Ctrl+C`，此时可改用快捷键，或先复制文本再用「翻译剪贴板内容」。
- 钩子生效期间，拖拽窗口、拖拽文件不会被误判为选词：未取到文本时静默放弃，并还原剪贴板。
- 语言判断基于字符区间的启发式规则，混排文本可能被判为占比更大的语种。

## 隐私说明

划选到的文本会通过 HTTPS 发送到你配置的 DeepSeek 接口用于翻译，除此之外不发起任何网络请求，也不上传任何本地数据。

## 设计约束（改代码时请遵守）

- **鼠标钩子回调里只允许记录状态**（几何判断、入队）。钩子由系统在消息泵内部同步调用，回调里做 Tk 操作会重入消息泵，最坏情况是递归到栈溢出把进程打死，表现为“鼠标变卡、几秒后程序消失”。
- **剪贴板只能在 worker 线程里碰**。`OpenClipboard` 是跨进程独占锁，可能被别的程序占住几百毫秒到几秒；在主线程等待期间，鼠标钩子无法被及时服务，整机鼠标都会卡。
- 弹窗的关闭是“先隐藏、160ms 后再销毁”，避免在鼠标按键仍按下时销毁窗口（隐式鼠标捕获会指向已销毁的窗口）。

`tools/screenshot_ui.py` 可把设置窗口与弹窗渲染成 PNG，便于核对排版（需 Pillow）。

取词没反应时，先把配置文件里的 `debug` 改成 `true` 并重启，再复现一次，然后查看 `%APPDATA%\Trans\trans.log`：能看到「检测到划选」说明钩子正常，只卡在后续环节；完全没有记录则用下面的探针确认鼠标事件是否被系统送到程序。

程序会把异常、硬崩溃的调用栈和主线程卡顿（`WARN 主线程卡住 …（最近动作：…）`）一并写进同一个日志文件，排查卡顿或闪退时先看它。

```powershell
python tools/hook_probe.py 20   # 20 秒内划选文字，打印收到的事件与“注入”标记
```
